Self-hosting

Documentation

Trycord is a Node.js server plus a web client it serves itself. This page covers running it, building the desktop app, and deploying an instance. It assumes a checkout of the repository.

Requirements

  • Node.js (the modern release line).
  • SQLite (default, zero setup) or a MySQL database for production.
  • Nothing else is required to run the server and serve the web client.

Running the server

From backend/:

copy .env.example .env   # then edit .env

The server refuses to start without two things: a JWT_SECRET and a database. Generate a secret with:

node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

For local development, the example file configures SQLite with a file database:

DB_CLIENT=sqlite
          DB_FILE=./dev.db

Start the server:

node src/server.js

The server serves the web client at its root — open http://localhost:<PORT> (default 9971) in a browser. Some transports are only served over real http(s):// origins, so open it over the network rather than file://.

Add ADMIN_USERNAMES=alice,bob (comma-separated) to promote existing accounts to platform admins at boot. The operation is idempotent, so it is safe to leave in .env permanently. Accounts that do not exist yet are skipped with a warning — create the account first, then restart (or re-run) to promote it.

Configuration reference

Every setting is an environment variable documented in backend/.env.example. Highlights:

VariablePurpose
SERVER_HOST_TYPEexpress (direct) or nginx (behind a reverse proxy). Exactly one; anything else fails at startup.
PORTListen port (default 9971).
JWT_SECRETRequired signing secret, unique per instance.
TRYCORD_NAMEInstance display name shown to users.
TRYCORD_PUBLIC_URLPublic base URL of this instance (optional, informational).
PUBLIC_URLUsed for absolute links such as password-reset emails. Never derived from request headers.
MAIL_MODElog (dev default) or smtp for real password-reset and verification email.
DB_CLIENTsqlite or mysql. Pick exactly one profile.
ADMIN_USERNAMESComma-separated usernames promoted to platform admin at boot.
CSP_CONNECT_ORIGINSExtra origins the client may reach (for browsing other instances).
TRUST_PROXYSet to 1 only when nginx fronts the server on the same host.

The web client

The client lives in frontend/ and resolves its API origin at runtime with a strict precedence: a ?api= query parameter, a saved setting, the server-pinned runtime config, the page's own origin, and finally http://localhost:9971. You can point the client at a different instance by launching the app with --api or by opening the page with ?api=<url>.

Desktop builds

From trycord-desktop/ (requires an Electron toolchain):

npm run build:win     # Windows (installer + portable)
          npm run build:linux   # Linux AppImage
          npm run build:mac     # macOS
          npm run smoke         # quick headless smoke test of the packaged app

Releases are published to the repository's Releases page and the desktop app auto-updates from them.

Deployment

For direct exposure, use SERVER_HOST_TYPE=express. For a reverse-proxy setup, set SERVER_HOST_TYPE=nginx (Express then binds loopback), TRUST_PROXY=1, and have nginx forward X-Forwarded-*; the server pins trust to loopback so remote clients cannot spoof forwarded headers.

The static public/ website can be hosted from anywhere — it is plain HTML, CSS, and one JavaScript file with relative links. In a reverse proxy you may serve it directly from the domain root and keep the app on a path, or serve it beside the app exactly as the Trycord server does. The server also exposes clean URLs for each page (for example /terms, /privacy, /features, /docs).

Security & API notes

Every page is served with a strict Content-Security-Policy: default-src 'self', no inline scripts, no cross-origin framing. Clients get a JSON error envelope, { error: { code, message } }, so failures are always machine-readable. The server applies rate limits to auth endpoints and WebSockets enforce a maximum payload size. Uploaded files are validated and rendered safely.

Lawful access endpoints of note: /api/health for liveness, /api/legal for the current legal document versions, and the WebSocket gateway for the real-time transport.

Testing

From backend/scripts/:

node check.js            # general checks
          node test-regression.js  # API regression suite
          node test-trustsafety.js # trust & safety flows
          node test-phase2.js      # phase-two feature coverage

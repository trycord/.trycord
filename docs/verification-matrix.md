# Verification matrix

Every surface the application offers, and how each one is actually exercised.

This file used to be generated by a script that rendered every route in jsdom
against a throwaway database. That script is gone, along with the rest of the
automated check suite, because running it on this host was costing more than the
product was worth. What is left is the honest position: which surfaces exist,
what they are built from, and how a person confirms each one.

Verification is now manual and against a running instance. Sign in, open the
surface, and watch the real request in the network panel. Where a surface
depends on another subsystem, that subsystem is the one being verified too.

| Surface | Route | Built from | How it is exercised |
|---|---|---|---|
| Home | `/home` | `features/home.js` | sign in and read the feed, the places and the announcements |
| Direct messages | `/dms` | `features/dms.js` | open a conversation, send, reload and confirm the message persisted |
| A conversation | `/dms/:id` | `features/dms.js` + `ui/chat.js` | the timeline and the composer, with a second device to see the event arrive |
| Notifications | `/notifications` | `features/inbox.js` | trigger a mention and read it in the inbox by day |
| Discover | `/discover` | `features/discover.js` | search a public community and join it |
| Friends | `/friends` | `features/friends.js` | send a request, accept it from the other account |
| Command | `/menu` | `features/everything.js` | search for a page, a community or a person |
| Profile | `/users/:id` | `features/profile.js` | open a profile, change the name and the picture |
| Community | `/c/:slug` | `features/community.js` | open a community, read a channel, post in it |
| Channel members | `/server/:id/members` | `features/community.js` | open the member list, change a role |
| Channel roles | `/server/:id/roles` | `features/community.js` | create a role and see it apply |
| Channel invites | `/server/:id/invites` | `features/community.js` | create an invite and redeem it |
| Channel categories | `/server/:id/categories` | `features/community.js` | create a category and move a channel into it |
| New community | `/servers/new` | `features/documents.js` | create a community and land in it |
| Profile settings | `/settings` | `features/settingsAccount.js` | change the name, the status and the picture, reload and see it kept |
| Security | `/settings/security` | `features/settingsSecurity.js` | change the password, enrol a second factor, revoke a session |
| Privacy | `/settings/privacy` | `features/settingsSafety.js` | change the contact policy, block and unblock, export the data |
| Notifications | `/settings/notifications` | `features/settingsNotices.js` | change a channel's notification preference |
| Appearance | `/settings/appearance` | `features/settingsClient.js` | switch the theme and the density |
| Connection | `/settings/backend` | `features/settingsClient.js` | point the client at another instance and back |
| Updates | `/settings/updates` | `features/settingsClient.js` | read what this build is |
| Admin overview | `/admin` | `features/adminSurfaces.js` | read the instance counts |
| Admin people | `/admin/users` | `features/adminSurfaces.js` | search an account, suspend it, lift the enforcement |
| Admin approvals | `/admin/approvals` | `features/adminSurfaces.js` | approve a waiting account |
| Admin communities | `/admin/communities` | `features/adminSurfaces.js` | read the community list |
| Admin reports | `/admin/reports` | `features/adminSurfaces.js` | resolve a report |
| Admin appeals | `/admin/appeals` | `features/adminSurfaces.js` | decide an appeal |
| Admin audit | `/admin/audit` | `features/adminSurfaces.js` | read the administrative trail |
| Admin data requests | `/admin/gdpr` | `features/adminSurfaces.js` | review and process a request |
| Admin announcements | `/admin/announcements` | `features/adminInfra.js` | post an announcement and read it on Home |
| Admin pages | `/admin/pages` | `features/adminInfra.js` | publish, unpublish and restore a public page |
| Admin configuration | `/admin/settings` | `features/adminCfg.js` | change a setting and see the effective value change |
| Admin database | `/admin/database` | `features/adminInfra.js` | test a configuration, apply it, roll it back |
| Admin Continuum | `/admin/continuum` | `features/adminInfra.js` | turn federation on, add a peer, trust it, read the outbox and the inbox |
| Instances | `/instances` | `features/instances.js` | list the known instances, or give an address and connect to it |
| Sign in | `/login` | `features/auth.js` | sign in with a real account |
| Register | `/register` | `features/auth.js` | create an account on the instance in force |
| Forgot password | `/forgot` | `features/auth.js` | request a reset and redeem the link |
| Invite | `/invite/:code` | `features/documents.js` | redeem an invite and land in the community |
| Public pages | `/legal/:doc`, `/support` | `features/documents.js` | read them as a visitor |

The Mobile module carries the same destinations in its own views, and the
shared platform beneath both is the same code.

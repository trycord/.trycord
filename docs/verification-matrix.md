## What each column means, and what measured it

- **Reachable** — a hard GET to the URL returns the shell, so a refresh or a bookmark works
- **Renders** — the surface renders without an uncaught fault
- **Heading** — exactly one h1, or the surface is documented as chrome-less
- **Controls** — every button and link has an accessible name
- **States** — loading, empty, error and success states exist
- **Responsive** — usable at phone width
- **a11y** — keyboard reachable, named, reduced-motion respected
- **Notes** — anything about the surface a reader needs to know.

## Known gaps

Recorded rather than hidden, so nobody reads a dash as a pass:

- **States, Responsive and a11y are not yet measured per page.** The harness
  asserts them across the whole run (1365 controls carry accessible names, and
  `check-mobile-layout.js` covers the phone composition), but not per route.
  Filling those columns is phase one of the rebuild.
- **The public site is on the canonical tokens but not yet redesigned.** It
  consumes the asset library's palette, type, spacing and radii — verified by
  `check-public-site.js`, which fails on any raw colour in `site.css` — but its
  layout is still the one it had before. Sharing a design system is not the
  same as a redesigned composition, and the mobile frontend brief covers both.

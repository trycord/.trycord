# Verification matrix

Every surface the application offers, and how each one is actually exercised.

This file used to be generated by a script that rendered every route in jsdom
against a throwaway database. That script is gone, along with the rest of the
automated check suite, because running it on this host was costing more than the
product was worth.

**A suite is back, and this is how it works now.** The replacement does not
render a route to find out whether a route renders: it starts a real instance —
a temporary database, a free port, its own signing secret — and asks it what
it answers. So a surface is verified by the request that reaches it, and the
column on the right says which test does it.

```
cd backend && npm test                    # everything
cd ../frontend && node --test "tests/**/*.test.js"   # the client
cd ../public && node --test "tests/**/*.test.js"     # the public website
cd ../sdk/trycord-botjs && npm test                  # the SDK
cd ../frontend && node scripts/browser-sweep.mjs     # every route, in a browser
```

The checks that are not tests run on their own:

```
cd backend && npm run check:names        # the client: names, paths, overlay options
cd backend && npm run check:names:backend  # the backend: the same, and the route definitions
cd backend && npm run check:contract      # the paths the client asks for, against the routes there are
```

The browser sweep is a real Chromium, real CSS and real pixels. The instance's
answers are stubbed, because the browser in this environment cannot reach the
network; the layout, the clipping, the touch targets, the accessible names
and the console errors are all real.

Where a surface depends on another subsystem, the test exercises that one too:
the federation relay is proved between two independently running instances with
separate databases and separate keys, not against a mock.

## The subsystems that are not screens

Some of the product has no interface at all, and that is deliberate or it is
recorded. These are verified by their own suites.

| Subsystem | Verified by | What it proves |
|---|---|---|
| End-to-end encryption | `tests/e2ee/`, `tests/integration/e2ee-messaging.test.js` | The protocol, the device lifecycle, the recovery, and the server refusing to store a plaintext in a conversation it reports as encrypted |
| Federation | `tests/continuum/` | Two independently running instances, a community crossing in both directions, and every relay rule proved in both |
| Extensions and workflows | `tests/extensions/`, `tests/workflows/` | The capability grants at call time, the sandbox, the loop prevention, the idempotency |
| The developer platform | `tests/developer/` | The scopes, the rotation, the OpenAPI document against the routes that serve it |
| Both dashboard modes | `tests/dashboard/` | The two modes are different code paths, and the separate service holds no database and no worker |
| The collaboration workspace | `tests/workspace/` | Spaces, documents with conflict detection, boards with version preconditions, events, polls |
| The migrations | `tests/integration/migrations.test.js` | The ledger, the ordering, the refusal of a database a newer build wrote to, and the separate identity every application gets |
| The voice relay | `tests/voice/turn-stack.test.js`, `tests/voice/mesh.test.js`, `tests/voice/join-race.test.js` | The STUN binding request, the TURN allocate, the credential that is issued per session, the refusal of a relay that does not answer, and two joins at once leaving one participant row |
| The schema's portability | `tests/integration/schema.test.js` | Every declared column is legal on MySQL, and every table is declared after the tables it points at |
| The outbound guard | `tests/integration/netguard.test.js` | A private address is refused, and the function the callers import exists |
| The environment template | `tests/integration/environment-template.test.js` | Every variable the code reads is documented, and every variable documented is read |
| The provider catalogue | `tests/integration/providers.test.js` | The console and the service cannot disagree about what a provider is |
| Push devices | `tests/integration/push.test.js` | The registry, the ownership, and the erasure taking it with the account |
| The native client | `native/scripts/check-native.mjs` | Every import resolves and every configuration file parses. **It was not compiled, run or put on a device** — there is no toolchain for it here |
| The names and the paths | `backend/scripts/check-backend-names.mjs`, `frontend/scripts/check-client-names.mjs` | Every name a module reads is declared, every relative path it asks for resolves to a file, every route definition is read by the router, and every option an overlay is given is one the overlay reads. Four bugs of this kind had shipped: a relay address read through a path that did not exist, a saved worker count read the same way, a dialog whose buttons were never drawn, and a bot that was told it was hearing events it was not |
| The client and the server agree | `backend/scripts/check-api-contract.mjs` | Every path the client and the SDK ask for is a route the server registers. The SDK had this fault: its command and health helpers asked for routes that do not exist |

## What is not verified here, and why

- **Nothing was verified by looking at it.** Chromium cannot reach the network
  in this environment, so the browser sweep runs against a stubbed instance:
  the layout, the clipping, the touch targets and the accessible names are
  real, and the answers behind them are not. There is no visual check of any
  surface, no real focus-trap exercise, and no screen-reader pass. The client
  is verified by driving it in Node against a stub DOM, and the two contracts
  that matter most — the account and the recovery — are verified against a
  real running instance over HTTP.
- **Two browsers were never put in a call.** No microphone, no camera and no
  second machine: the voice tests prove the signalling, the credential, the
  ICE list and the relay, and the WebRTC media path itself was not exercised
  end to end.
- **The native client was never built.** No JDK, Gradle, Android SDK, Xcode or
  macOS. `native/VERIFICATION.md` states item by item what is and is not
  checked.
- **No independent cryptographic review was obtained.** The E2EE implementation
  has an internal self-review, which names its own limits, and no third party
  has looked at the key schedule or the ratchet.
- **The deployed instance was checked over HTTP, not in a browser.** The
  cross-origin defects in the public site were found by reading the code and
  are fixed with tests; the deployed behaviour after the fix was verified over
  HTTP, not by loading the page.
